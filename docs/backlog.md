# 백로그 (추후 일감)

지금 구현하지 않는 계획 항목. 착수할 때 이 문서의 항목을 설계 문서/계획으로 옮긴다.

## 1. 후원 위젯 (헤더 좌측) — 구현 완료 (2026-11-27)
- 헤더 좌측, 사이트 이름 `IT Security Blog` 왼쪽에 "커피 한 잔 후원하기" 버튼(커피잔 아이콘 + 글자). 프로필 링크 서비스 리틀리(litt.ly)의 `https://litt.ly/theman`으로 연결되는 **외부 링크이며 새 탭**(`target="_blank"`, `rel="noopener noreferrer"`)으로 열린다.
- 링크 변경(2026-11-28): 처음에는 후원 플랫폼 크티(`https://ctee.kr/place/theman`)로 연결했고 리틀리로 바꿨다. 아래 근거는 크티 기준이지만 외부 링크 방식 결정은 그대로 유효하다.
- 방식 결정 근거: 크티는 "응원하기" 창이 크티 페이지 안에서 뜨는 구조이고 공식 임베드 위젯/배지 기능을 찾지 못했다. 크티 페이지는 Google Tag Manager/Analytics/Facebook 픽셀을 불러오므로 iframe/스크립트로 임베드하면 추적 스크립트가 우리 페이지에서 동작해 개인정보·성능에 영향을 준다. 외부 링크는 우리 사이트에 외부 스크립트를 들이지 않는다.
- 배치(2026-11-27 갱신): 사이트 이름 **오른쪽**, 내비 왼쪽. 글자는 두 줄("커피 한 잔" / "후원하기"), 폰트는 카페24 숑숑(OFL 1.1, 서브셋 16KB, `src/assets/fonts/`), 아이콘은 글자 두 줄 높이에 맞춰 키우고 굵은 선(stroke 2.25).
- 위치와 수정 지점: `src/components/header.js`의 `SUPPORT_URL`과 `SUPPORT`(문구·aria-label). 문구를 바꾸면 폰트 서브셋(`Cafe24Syongsyong-subset.woff2`)에 새 글자가 없을 수 있으니 NOTICE 파일의 재생성 명령으로 다시 만든다, 스타일은 `src/styles/shell.css`의 `.support-widget`(토큰 기반, 라이트/다크 자동, 1100px 이상에서만 글자 표시, 그 미만은 아이콘만, 860px 미만은 헤더가 2행으로 접힘).
- 개인정보처리방침(`src/content/privacy.md`)에 "외부 링크(후원)" 항목을 추가했다. 리틀리 링크 주소나 서비스를 바꾸면 이 항목도 함께 고친다.
- 테스트: `tests/e2e/static.spec.js`(위젯 속성, 위치, 새 탭, 테마 색, 폭별 오버플로 없음), `tests/e2e/a11y.spec.js`(탭 순서: 위젯 → 사이트 이름 → 내비 → 토글).
- 남은 선택 사항: 후원 클릭 집계가 필요하면 방문자 통계 도입(항목 2)과 함께 설계.

## 2. 방문자 통계 / 광고 (AdSense 등)
- 도입 전에 `src/content/privacy.md`(개인정보처리방침)를 먼저 갱신한다: 수집 항목, 쿠키/식별자, 목적, 거부 방법, 제3자 제공. 현재 방침은 "통계/광고 미사용" 기준이다.
- 도입 시 쿠키 동의(해당 지역 규정), 성능 영향(외부 스크립트), CSP, `docs/seo.md`의 Lighthouse 재측정을 함께 한다.

## 3. 기타
- 파비콘(`index.html`은 `data:,`로 404만 막는 상태), `llms.txt`, 서버 측 글 본문 프리렌더(`docs/seo.md` 한계 항목), 문의처: `/contact`(footer "문의하기")는 지금 "준비 중" 안내만 있는 페이지(`src/content/contact.md`). 색인(noindex 해제)과 sitemap 포함은 이미 켜 둔 상태라, 내용이 얇은 동안은 검색 품질에 불리할 수 있으니 문의처(메일/폼)가 정해지면 빨리 `contact.md`를 채우고, About/개인정보처리방침의 "곧 추가됩니다" 문구도 갱신한다.
