# 백로그 (추후 일감)

지금 구현하지 않는 계획 항목. 착수할 때 이 문서의 항목을 설계 문서/계획으로 옮긴다.

## 1. 후원 위젯 (헤더 좌측)
- **요청(2026-11-27):** 헤더 좌측, 사이트 이름 `IT Security Blog` **왼쪽**에 후원 위젯을 둔다. 당장 구현하지 않고 문서에만 기록한다.
- **미정(착수 전에 정할 것):**
  - 후원 수단/서비스(예: 외부 후원 링크 버튼인지, 서비스가 제공하는 임베드 위젯인지)와 표시 문구.
  - 외부 스크립트/iframe을 쓰는 경우: 성능(LCP/CLS 영향, 지연 로딩), 개인정보처리방침(`/privacy`)에 항목 추가, CSP, 쿠키 사용 여부.
  - 레이아웃: 헤더의 `.site-header__inner`는 현재 [사이트 이름 | 내비 | 테마 토글] 구조. 모바일(≤639px)은 1행에 이름+토글, 2행에 내비. 위젯 폭을 포함해 390px에서 넘치지 않아야 한다(`tests/e2e/screens.spec.js`의 390px 헤더 테스트가 이를 검사).
  - 접근성: 키보드 탭 순서(위젯 → 사이트 이름 → 내비 → 토글), 명확한 접근 가능한 이름, 포커스 링.
  - 디자인: `DESIGN.md` 토큰만 사용(하드코딩 금지), 라이트/다크 대칭, 위계상 사이트 이름보다 튀지 않게.
- **완료 기준 초안:** 위젯 표시, 라이트/다크 대응, 390px/1440px 오버플로 없음, Lighthouse 모바일 Performance 90 이상 유지, 개인정보처리방침 갱신, Playwright 테스트 추가.

## 2. 방문자 통계 / 광고 (AdSense 등)
- 도입 전에 `src/content/privacy.md`(개인정보처리방침)를 먼저 갱신한다: 수집 항목, 쿠키/식별자, 목적, 거부 방법, 제3자 제공. 현재 방침은 "통계/광고 미사용" 기준이다.
- 도입 시 쿠키 동의(해당 지역 규정), 성능 영향(외부 스크립트), CSP, `docs/seo.md`의 Lighthouse 재측정을 함께 한다.

## 3. 기타
- 파비콘(`index.html`은 `data:,`로 404만 막는 상태), `llms.txt`, 서버 측 글 본문 프리렌더(`docs/seo.md` 한계 항목), 문의처: `/contact`(footer "문의하기")는 지금 "준비 중" 안내만 있는 페이지(`src/content/contact.md`). 색인(noindex 해제)과 sitemap 포함은 이미 켜 둔 상태라, 내용이 얇은 동안은 검색 품질에 불리할 수 있으니 문의처(메일/폼)가 정해지면 빨리 `contact.md`를 채우고, About/개인정보처리방침의 "곧 추가됩니다" 문구도 갱신한다.
